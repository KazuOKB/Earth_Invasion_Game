# アーキテクチャ設計書

## 1. この文書の目的

この文書は、新しいPythonコードの分け方をまとめます。

目標は次の3つです。

- 読みやすくする
- テストしやすくする
- 後から変更しやすくする

難しい仕組みは必要になるまで追加しません。

## 2. 基本方針

ゲームのルールとPygameの処理を分けます。

```text
Pygameの入力
    ↓
ゲーム用の命令
    ↓
ゲーム状態を更新
    ↓
描画と音声
```

ゲームのルール側では`pygame`をimportしません。

## 4. 依存関係

依存関係は一方向にします。

```text
pygame_app → gameplay → Python標準ライブラリ
```

`gameplay`から`pygame_app`は参照しません。

## 5. gameplayの役割

`gameplay`はゲームのルールを持ちます。

- プレイヤー
- 敵
- 弾
- 移動
- 当たり判定
- ダメージ
- 侵略ゲージ
- ステージ進行
- ボスの出現判定
- クリア判定
- ゲームオーバー判定

Pygameの画像や音声は扱いません。

## 6. pygame_appの役割

`pygame_app`はPygame固有の処理を持ちます。

- ウィンドウを作る
- キーボード入力を受け取る
- マウス入力を受け取る
- 画像を描く
- 文字を描く
- 音を鳴らす
- 画面を切り替える

## 7. ゲーム状態の管理

ゲーム全体は`GameSession`が管理します。

`GameSession`は次の状態を持ちます。

- プレイヤー
- 敵の一覧
- プレイヤーの弾
- 敵の弾
- 現在の区間
- 侵略ゲージ
- スコア

敵は並列の配列で管理しません。
敵ごとに1つのオブジェクトを作ります。

## 8. 状態の名前

数字のフラグは使いません。
状態には名前を付けます。

```python
class GamePhase(Enum):
    METEOR = auto()
    CHASER = auto()
    SHOOTER = auto()
    BOSS = auto()
    CLEARED = auto()
    GAME_OVER = auto()
```

この名前はJSONの`id`と対応させます。

## 9. 時間の扱い

ゲーム内の時間は秒で扱います。

速度は「1秒で何ピクセル動くか」で表します。
Pygameのタイマーイベントでステージを進めません。

ゲームの更新は固定間隔で行います。
初期値は1秒に60回です。

```text
固定更新間隔 = 1 / 60秒
```

1フレームが長くなっても、一度に大きく動かさないようにします。

## 10. ステージ設定

ステージ時間は`src/earth_invasion/data/`のJSONから読み込みます。

設定をPythonパッケージ内に置くことで、インストール後も読み込めます。
起動時に`--data-directory`を指定すると、別の設定へ差し替えられます。

通常用とテスト用は同じ形式にします。

```json
{
  "profile": "normal",
  "invasion_target": 100,
  "phases": [
    {
      "id": "meteor",
      "duration_seconds": 30.0
    }
  ]
}
```

読み込み時に次を確認します。

- `profile`が空ではない
- `invasion_target`が0より大きい
- 必要な区間がすべてある
- 区間の順番が正しい
- 時間が0より大きい
- ボスの時間だけが`null`になっている

テスト設定で新しい画面を起動するコマンドは次のとおりです。

```bash
uv run earth-invasion --stage-profile test
```

画面を開かずに設定だけを確認する場合は、次のように実行します。

```bash
uv run earth-invasion --stage-profile test --check-config
```

プレイヤーと攻撃の共通設定は`gameplay.json`から読み込みます。
このファイルには次の値を置きます。

- 内部解像度
- 1秒あたりの更新回数
- プレイヤーの最大体力
- 被弾後の無敵時間
- ビームの発射間隔
- 敵を倒したときの侵略ゲージ増加量

## 11. 画面の拡大

750×500の内部画面を1つ作ります。
ゲームは内部画面へ描画します。

最後に内部画面をウィンドウへ拡大します。
縦横比は維持します。

```text
倍率 = min(ウィンドウ幅 / 750, ウィンドウ高さ / 500)
```

拡大した画面は中央に置きます。
余った部分は黒で表示します。

マウス座標は内部画面の座標へ変換します。

## 12. 入力

Pygameのキーを、そのままゲームへ渡しません。

入力を次のような命令へ変換します。

```python
@dataclass(frozen=True, slots=True)
class PlayerCommand:
    vertical_direction: int
    fire_pressed: bool
```

`vertical_direction`は次の値を使います。

- `-1`: 上
- `0`: 移動なし
- `1`: 下

## 13. ゲームイベント

ゲーム内で起きたことをイベントとして返します。

例は次のとおりです。

- 敵を倒した
- プレイヤーがダメージを受けた
- 区間が変わった
- ボスが登場した
- ゲームをクリアした

Pygame側はイベントを見て、音や演出を再生します。

最初から大きなイベントシステムは作りません。
更新結果としてイベントの一覧を返します。

## 14. 当たり判定

最初は四角形の当たり判定を使います。

プレイヤー、敵、弾は当たり判定用の大きさを持ちます。
画像の大きさと当たり判定の大きさは分けられます。

必要になった場合だけ、画像の形に合わせた判定を検討します。

## 15. 乱数

乱数は`GameSession`の外から渡します。

```python
random_source = random.Random(seed)
```

テストでは同じ`seed`を使います。
同じ条件で同じ敵を出せます。

## 16. テスト方針

画面を開かないテストを中心にします。

最初に次をテストします。

- 時間で区間が進む
- テスト設定では短時間でボスまで進む
- 敵を倒すと侵略ゲージが増える
- 侵略ゲージが足りない場合はボスが出現しない
- 侵略ゲージが満タンになるとボスが出現する
- 終盤の設定時間より前にはボスが出現しない
- 無敵時間中は追加のダメージを受けない
- ビームは発射間隔より早く発射されない
- 攻撃が当たると体力が減る
- ボスを倒すとクリアになる
- 体力が0になるとゲームオーバーになる
- 同じ乱数シードで同じ結果になる

Pygame側では最低限の起動テストを行います。

自動テストでは、実際に2秒待ちません。
更新処理へ経過時間を直接渡します。

## 17. 読みやすさのルール

- 1つの関数に多くの仕事をさせない
- 短く意味が分かる名前を使う
- 型ヒントを書く
- 数字へ名前を付ける
- コメントには理由を書く
- 同じ処理を複数の場所へ書かない
- 難しい抽象化は必要になるまで作らない

テストも使用例として読める形にします。

## 18. 採用しないもの

最初の実装では次を使いません。

- 本格的なECS
- DIコンテナ
- グローバルなイベントバス
- 深い継承
- 必要性のない抽象クラス

## 19. 既存コードからの移行

新しい実装が動くまで、現在のゲームは残します。

移行は次の順番で行います。

1. uv環境と新しい起動処理
2. 固定サイズの画面
3. プレイヤー移動
4. ビーム
5. 敵と当たり判定
6. ステージ進行
7. 侵略ゲージ
8. ボス
9. タイトルと結果画面
10. 旧コードの削除

各段階でテストを追加します。
